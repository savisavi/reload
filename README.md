# RELOAD

Пиксельный киберпанк-данж: автономные наёмники, убежище, которое растёт с улучшениями, глубины серверной с биомами и ловушками, чертежи и 3D-принтер, рейтинг игроков.

Игра — это одна HTML-страница (canvas, без фреймворков). Небольшой сервер на Node.js без зависимостей отдаёт её и хранит аккаунты, сохранения и рейтинг.

## Структура

```
reload/
├─ src/
│  ├─ index.html        оболочка страницы: стили, разметка HUD, место /*CODE*/ под код игры
│  ├─ game/            код игры, модули склеиваются по порядку имён (01-…, 02-…)
│  │   01-core.js         генератор персонажей, RNG, палитры
│  │   02-items.js        оружие, броня, импланты, расходники
│  │   03-props.js        декорации, компоненты, таблицы лута
│  │   04-world.js        генерация карт и биомов
│  │   05-game_all.js     движок: рейд, бой, ИИ наёмника, рендер, убежище
│  │   06…31              системы поверх движка (убежище, зоны, ловушки,
│  │                      топливо, чертежи, комнаты, заставка, CRT и т. д.)
│  └─ vendor/fx.js     библиотека пиксельных эффектов (window.PFX)
├─ public/             статика, копируется в dist как есть (favicon)
├─ scripts/build.mjs   сборка: src → dist/index.html + dist/fx.js
├─ server/
│  ├─ index.js         HTTP-сервер: статика из dist/ + API
│  └─ store.js         хранилище: JSON-файлы в DATA_DIR
├─ railway.json        настройки деплоя на Railway
└─ package.json
```

Поздние модули расширяют ранние: оборачивают функцию (`const _f=f; f=function(){…}`). Новый модуль — новый файл с номером в `src/game/`.

## Локальный запуск

Нужен Node.js 18+.

```bash
npm run dev          # сборка + сервер на http://localhost:3000
npm run build        # только сборка в dist/
npm run build:debug  # сборка с window.__dbg для отладки в консоли
npm start            # только сервер (dist/ должен быть собран)
```

Данные сервера локально лежат в `./data` (в git не попадает).

## Деплой на Railway

1. Залейте репозиторий на GitHub.
2. Railway → **New Project → Deploy from GitHub repo** → выберите репозиторий. Railway сам увидит `package.json` и `railway.json`: соберёт `npm run build`, запустит `npm start`, проверит `/api/health`.
3. **Обязательно добавьте Volume** (правый клик по сервису → Attach Volume), путь монтирования, например, `/data`. Сервер сам найдёт его через переменную `RAILWAY_VOLUME_MOUNT_PATH`. Без тома аккаунты, сохранения и рейтинг сотрутся при каждом новом деплое.
4. Settings → Networking → **Generate Domain** — получите адрес игры.

Каждый `git push` в основную ветку запускает новый деплой.

### Переменные окружения (необязательные)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `PORT` | 3000 | порт; Railway задаёт сам |
| `DATA_DIR` | путь тома или `./data` | где хранить аккаунты и сохранения |

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | проверка живости |
| POST | `/api/auth` `{login,password}` | вход; если логина нет — создаёт аккаунт. Отдаёт токен и сохранение |
| GET/PUT | `/api/save` (Bearer-токен) | прочитать / записать сохранение и статистику |
| GET | `/api/top` | рейтинг: наёмники, лут, касса, глубина |

Пароли хранятся только как scrypt-хэши с солью, наружу не отдаются. Неверный пароль 10 раз за 10 минут — пауза для этого IP.

## Хранение

- `DATA_DIR/db.json` — аккаунты, сессии, статистика для рейтинга.
- `DATA_DIR/saves/<id>.json` — сохранение игрока.

Сохранение пишется и в браузер (localStorage), и на сервер (раз в 30 с и при сворачивании вкладки). При входе берётся более свежая копия, поэтому можно продолжить с другого устройства. Без сервера (файл открыт локально) игра работает только с localStorage.

Хранилище рассчитано на один экземпляр сервера. Для нескольких реплик нужна общая БД (например, Postgres на Railway) вместо `server/store.js`.
